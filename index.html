Main findings

We add test-time training (TTT) memory to pretrained Flex-π to test whether earlier observations guide later actions.

Performance is uneven across tasks

With 45 training demos per task, success reaches 95% on block rearrangement, 94% on block ordering, and 84% on block return, but only 38.1% overall. The model learns several manipulation sequences reliably from few demonstrations, while hidden-target selection (4%) and counting (3%) remain weak. High success on individual tasks does not establish reliable use of past cues across the benchmark.

Memory content guides the return location

Replacing memory with another episode’s memory redirected the robot toward that episode’s starting mat in 8/8 block-return trials. This intervention provides causal evidence that stored episode information influences target selection in this task; the success rate alone would not establish that.

Retaining history helps when blocks must return to earlier locations

In the 200-demo runs, TTT memory achieves 20/20 on block return and 8/20 on multiple-block return, versus 7/20 and 0/20 for w/o persistent memory, which resets TTT state during both training and evaluation. Block swapping is closer: 17/20 vs. 15/20. The clearest benefits here are on tasks requiring a return to an earlier location; persistent memory does not improve every task equally.

Training with memory can make a policy depend on it at evaluation

In the earlier reported 16-step block-ordering comparison, resetting the same 6k checkpoint only at evaluation drops success from 26/100 to 0/100. A separate model trained and evaluated with resets reaches 30/100. The trained policy depends on its accumulated memory, while a policy trained under reset can still succeed. This makes training-time memory behavior part of the evaluation protocol.

These ablations test retention across calls. All TTT variants still update and read within each call, so they do not establish that disabling updates during either training or evaluation causes failure.

Transfers improve with expanded training; ordered uncovering remains difficult

With 200 demos/task (≈195 training), block swapping rises from 6/20 to 17/20 and multiple-block return from 0/20 to 8/20. With 500 demos/task (495 training), T-block swapping rises from 2/20 to 16/20, while block return reaches 20/20. These gains suggest that more task-specific training can address some of the low-data failures.

Ordered uncovering stays at 1/20 with 200 demos, despite successful covering in 20/20 episodes. This localizes the remaining difficulty to uncovering the blocks in the required color order: adding demonstrations has not yet resolved that stage.

Comparisons use the same 20 validation seeds per task and 20k training updates. Task groups also change from 10 to 4 to 2, so the gains cannot be attributed to data volume alone.

battery_try

The second battery slips during placement

The second battery is lowered about 3 cm off target, toward the first battery’s position. It slips during the descent and falls onto the table. The policy keeps adjusting the first battery without retrieving the second.

swap_T

The blocks change sides, but the second T has the wrong angle

The second T is placed about 17° from the target orientation; the task allows 15°. Later adjustments also rotate the first T away from its target orientation.

cover_blocks

The robot covers the blocks but often chooses the wrong lid to uncover

The blocks must be uncovered in red, green, and blue order after their colors are hidden. In the failed rollout above (seed 200002), the robot removes the middle lid first; the evaluator records the order violation at step 637.

In the ten-task B3 test run, the robot covered all three blocks in 100/100 episodes, selected the correct first lid in 29/100, and completed the task in 6/100. For reference, choosing uniformly among three lids gives a 1/3 probability of selecting the correct first lid.
